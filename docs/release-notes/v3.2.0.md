# v3.2.0 — maintenance release: launcher rework, WebUI fixes, upstream hardening

> 2026-08-02 · 12 commits since v3.0.0 · focused on reliability and usability

v3.2.0 is a maintenance release on top of the v3.0.0 React WebUI
rewrite. It reworks the Windows launcher, fixes a batch of WebUI bugs
(including a blank-page asset-404 issue), rewrites the Playground around
the parameters that actually reach DeepSeek, hardens the adapter against
empty upstream responses, and aligns request headers with the current
browser release.

---

## Highlights

### start.bat rework

- **Auto-provision a virtualenv** — detects `.venv` / `venv` / `env`, or
  creates `.venv` with the system Python 3.10+
- **Dependency check** — `pip install --dry-run` verifies requirements and
  installs them automatically when missing
- **WebUI auto-build** — runs `npm install && npm run build` in
  `webui-new/` when `dist/` is absent (`WEBUI_REBUILD=1` forces a rebuild)
- **Print access URLs and open the browser** — shows WebUI / API / health
  endpoints and auto-opens `/webui/` 3s after startup (`WEBUI_OPEN=0` skips)
- **Safe port handling** — only kills processes whose command line matches
  the project (`uvicorn` / `server:app` / `server.py` / `ds2api`), using
  PowerShell `Get-CimInstance` instead of the removed `wmic`; refuses to
  kill unrelated processes
- GBK + CRLF encoding for reliable output in zh-CN `cmd`

### WebUI fixes and polish

- **Asset 404 / blank page fixed** — the built SPA referenced root-path
  assets while the backend only serves `/webui/*`; `vite.config.ts` now
  sets `base: '/webui/'` and the router uses `basename: '/webui'`
- 7 functional bug fixes: dead "View API" link (always 401), SSE parser
  CRLF/trailing-buffer handling, stale-closure empty assistant messages on
  stop, dead-code cleanup, keyboard accessibility for account rows
- **Playground rewrite** — parameters now mirror what the backend actually
  forwards (`model` → `model_type`, `thinking_mode` → `thinking_enabled`,
  `search_enabled`); the ineffective temperature slider was removed;
  expert-mode `reasoning_content` renders in a collapsible "Reasoning" block
- **Quick / Expert model modes** — `MODEL_ROUTES` enabled by default so the
  model dropdown offers `deepseek-chat (quick / default)` and
  `deepseek-reasoner (expert)`
- UI polish: gradient slider, message bubbles, Skeleton loading states,
  AlertDialog confirmations

### Server & auth

- **Admin token on `/v1/*`** — `_check_api_auth` accepts a valid
  admin-session token (`verify_admin_token`), so the WebUI's model list and
  Playground no longer bounce to `/login` on 401
- **Env credentials as pool fallback** — `.env` credentials are no longer
  pre-loaded into the pool; they act as a read-only fallback used only when
  the pool has zero accounts (panel-managed accounts take priority; empty
  pool no longer returns 503)

### Upstream hardening

- **Empty-response retry** — the upstream occasionally returns HTTP 200
  with an empty SSE body; `chat()` / `chat_stream()` now retry once with a
  fresh session (`UpstreamEmptyError`) and surface a clear 502 (non-stream)
  or error frame (stream) instead of a silent 200 with empty content
- **Headers aligned with the browser** — `X-Client-Version` 2.0.0 → 2.3.0,
  removed the obsolete `X-App-Version` (verified against a live HAR); the
  new `x-hif-leim` / `x-hif-dliq` signature-head mechanism was reverse
  engineered and documented (see AGENTS.md) for future enforcement

## Upgrade notes

- `start.bat` now manages the virtualenv itself — remove any manual
  `venv`/`.venv` you no longer want, or let it reuse the existing one
- WebUI builds to `webui-new/dist/`; a fresh build is required for the
  Playground / asset fixes to appear (start.bat does this automatically)
- `.env.example` now ships `MODEL_ROUTES` enabled by default
- No breaking API changes; `/v1/*` and `/admin/api/*` behave as before

## Verified

- 56 pytest unit tests green
- End-to-end: streaming + non-streaming chat, expert reasoning output,
  WebUI asset chain, admin login, pool fallback, browser auto-open
